# 02. ネームドキャラ設計指針

対象: ジムリーダー・四天王・チャンピオン・ライバル・悪の組織のボス等、名前を持つトレーナー全て。
関連: [`battle-system.md`](battle-system.md) / [`../game-plan.md`](../game-plan.md) 5章

---

## 1. 基本方針：キャラらしさ優先

**決定事項: 強化ティアの構築は「対戦環境的な強さ」ではなく「キャラらしさ」を優先する。**

この決定がなぜ重要か。強さだけを追うと、全ネームドが環境最強ポケモンに収束し、
「誰と戦っても同じ」になる。ジムリーダー30人ぶんのデータを作っても、
体験としては1人ぶんにしかならない。**キャラらしさこそが、
ネームドを大量に実装することの唯一の見返り。**

### 中心原則

> **そのキャラの「専門」の中で最強を目指す。専門の外には出ない。**
> 強化は「幅」ではなく「深さ」で行う。

## 2. 強化の具体的なやり方

### やること（深さ）

| 手段 | 内容 |
| --- | --- |
| 持ち物 | きあいのタスキ、こだわり系、半減実、ゴツゴツメット、たべのこし |
| 特性の選択 | 複数候補から最も戦術に噛み合うものを選ぶ |
| 努力値・性格 | 役割に沿って最適化（耐久型・全抜き型など明確に） |
| **戦術の付与** | 天候・フィールド・トリックルーム・積み技・場作り（ステルスロック等） |
| AI の賢さ | 交代読み・積みのタイミング・耐久計算（[`ai.md`](ai.md)） |
| レベル統一 | 「本気」= Lv50、「極」= Lv50（構築の質で差をつける） |

### やらないこと（幅）

- ❌ **専門外のポケモンを弱点補完のために入れる。** いわ使いに みず を入れて弱点を消す、等。
- ❌ **環境トップメタを借りてくる。** そのキャラと関係ない汎用最強枠は使わない。
- ❌ **全キャラが同じ戦術に収束する。** 砂・トリル・雨などの戦術は**キャラ間で重複させない**よう台帳で管理する。

### 弱点の扱い

**弱点は消さない。「弱点を突かれた時にどうするか」で答える。**

これが「らしさ優先」の核心。弱点を消すと、そのキャラである意味がなくなる。
代わりに、専門の内側にある解決策を与える。

- でんき使いの じめん 弱点 → ふゆう持ち／でんじふゆう／エレキフィールドで対応する（でんきの内側の解決）
- 弱点を突かれる前提で、**先に積んで押し切る**構築にする
- きあいのタスキ + 一撃で返す、という割り切った構築にする

## 3. 許容範囲のルール（グレーゾーンの判定基準）

「専門の外に出ない」を厳格にやりすぎると構築が組めないキャラが出る。以下を許容する。

| 判定 | ルール | 例 |
| --- | --- | --- |
| ✅ 許容 | **進化・リージョンフォームによる複合タイプ** | むし使いが ストライク→ハッサム（むし/はがね）を使う |
| ✅ 許容 | **極ティアでは全地方のポケモンを使ってよい** | ジョウトのむし使いがイッシュのむしポケモンを使う |
| ✅ 許容 | **隣接する自然なテーマの拡張** | いわ使いが じめん を併用（砂・地面という共通の質感） |
| ⚠️ 要検討 | 準専門タイプの多用 | 上記が構築の過半を占めたら「らしさ」を失っている |
| ❌ 不可 | 弱点補完だけが目的の異質なタイプ | いわ使いの みず、むし使いの ドラゴン |

**ただし、原作の手持ちの核（エース）は全ティアで必ず残す。**
極ティアで全地方から選べるようにしても、そのキャラを象徴する1体は不動。
これが「同じキャラだ」と認識できる最低条件になる。

## 4. カテゴリ別の「らしさ」の定義軸

| カテゴリ | らしさの軸 | 構築方針 |
| --- | --- | --- |
| ジムリーダー | 専門タイプ | タイプ純度が最も高い。1タイプで組み切る。 |
| 四天王 | 専門タイプ | ジムリーダーより格上。戦術の完成度で差をつける。 |
| チャンピオン | **バランスと総合力**（タイプ縛りなし） | 原作の手持ちを核に、隙のない6体。最高難度。 |
| ライバル | 主人公との対比 | 主人公の御三家に有利な御三家を軸に、幅広い構成。 |
| 悪の組織ボス | 組織のテーマ | 組織ごとのカラー（例: あく/どく 系、はがね 系）に従う。 |
| その他 | 個別に定義 | 職業・性格・原作での役割から `concept` を言語化する。 |

**チャンピオンだけがタイプ縛りを持たない**ため、必然的に最も強くなる。
これは意図的な設計で、難易度の頂点をチャンピオンカップに置くことになる。

## 5. 強さの格差をどう扱うか

キャラらしさを優先すると、**専門タイプの強さに由来する格差は必ず出る**。
むし使いは、どうやってもドラゴン使いより弱い。

**この格差は原作の再現として受け入れる。無理に均さない。**

代わりに以下で補償する。

- **弱いタイプのキャラには「戦術の意外性」を与える。** プレイヤーが油断して負ける形にする。
  正面から強いキャラより、記憶に残る戦いになりやすい。
- **難易度の調整はカップの編成で行う。** キャラ個体を強くするのではなく、
  出場者プールと勝ち抜き数で難度を作る（[`endgame.md`](endgame.md)）。
- **「極」の体験目標は「そのキャラの土俵で勝つ」こと。** 全キャラを同じ強さに揃えることではない。

## 6. 3ティアの定義

| ティア | レベル | 体数 | 持ち物 | 個体値/努力値 | 特性 | AI | 位置づけ |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **原作** | 原作準拠 | 原作準拠 | なし | 未最適化 | 既定 | `basic` | 地方攻略中に戦う姿 |
| **本気** | Lv50統一 | 4 | あり | 標準的に最適化 | 選択 | `basic` | 実戦的な構成。エンドゲーム入口。 |
| **極** | Lv50統一 | 6 | あり | 完全最適化 | 選択 | `smart` | 専門内での完成形。明確な戦術を持つ。 |

**ティア間で差し替えるのはパーティ定義のみ**で、キャラの人格・台詞・グラフィックは共有する。
キャラを1人追加すれば3段階ぶんのコンテンツになる。

## 7. データ表現

```ts
type NamedCharacter = {
  id: string;                    // "brock"
  name: string;                  // "タケシ"
  role: "gymLeader" | "elite4" | "champion" | "rival" | "villain" | "other";
  region: RegionId;              // "kanto"

  // ── らしさの定義（設計の中核。ここを先に言語化してから構築を組む）──
  concept: {
    type?: Type;                 // 専門タイプ。チャンピオンは null
    theme: string;               // "防御を固めて砂で削り切る"
    tactic?: TacticId;           // "sandstorm" — キャラ間で重複させない管理用
  };
  signature: SpeciesId;          // 全ティアで不動のエース

  tiers: {
    original: Party;
    serious: Party;
    ultimate: Party;
  };

  dialogue: Record<TierId, { before: string; win: string; lose: string }>;
};

type Party = {
  species: SpeciesId; level: number; moves: MoveId[];
  item?: ItemId; ability?: AbilityId; nature?: NatureId;
  evs?: StatSpread; ivs?: StatSpread;
}[];
```

### `concept` を必ず先に書く

パーティを組む前に `theme` を一文で言語化する。これができないキャラは、
構築を組んでも「らしさ」が出ない。**逆に言えば、`theme` さえ決まれば構築は自動的に決まる。**

`tactic` フィールドは戦術の重複検出用。データ検証スクリプト（`tools/`）で
「同じ戦術を持つキャラが3人以上いる」を警告できるようにする。

## 8. 作業手順（キャラを1人追加するとき）

1. `concept.theme` を一文で書く
2. `signature`（不動のエース）を決める
3. `tactic` を決め、既存キャラと重複しないか確認する
4. 原作ティアのパーティを原作データから移植する
5. 本気ティア = 原作の核を残しつつ Lv50・4体・持ち物ありに再構成
6. 極ティア = `theme` を最大化する6体。全地方から選んでよいが `signature` は必ず入れる
7. 台詞を3ティアぶん書く

## 9. 調整項目（実装後に決める）

- 極ティアの実際の強さが体感でどうか（Lv50統一で足りるか）
- AI `smart` の判断閾値
- 弱いタイプのキャラの体感難易度が許容範囲か
- 「本気」と「極」の間にもう1段階要るか
