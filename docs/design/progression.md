# 03. 育成システム

準拠世代: 第9世代
関連: [`battle-system.md`](battle-system.md) / [`capture.md`](capture.md) / [`regions.md`](regions.md)

---

## 1. 設計方針

育成システムの設計は、**この作品固有の事情**に強く縛られる。

> 地方独立チャレンジ制では、Lv5→60 の育成を**9回繰り返す**。
> 原作の育成テンポをそのまま9回やると、確実に「作業」になる。

一方で、エンドゲームの極ティアと戦うには**個体値・努力値の最適化が必須**になる。
つまり本作の育成は、

- **本編（地方チャレンジ）= 育成を軽くする。** 面白さは「新しいポケモンを使うこと」から来るので、レベル上げの時間は短縮してよい。
- **エンドゲーム = 育成を深くする。** ここで初めて個体値・努力値・性格を意識させる。

という**二段構え**にする。これが本章の全ての判断の根拠になる。

## 2. ステータス計算

```
HP     = floor( (2 × 種族値 + 個体値 + floor(努力値 / 4)) × Lv / 100 ) + Lv + 10
その他 = floor( ( floor( (2 × 種族値 + 個体値 + floor(努力値 / 4)) × Lv / 100 ) + 5 ) × 性格補正 )
```

- レベル・努力値・個体値が変わったときに再計算する。**バトル中は計算済みの値を持ち回る**（毎ターン再計算しない）
- ランク補正・状態異常による補正は**この計算結果に対してバトル側で掛ける**（[`battle-system.md`](battle-system.md) §6）。ここでは含めない

## 3. 個体値（IV）

- 6ステータスそれぞれ **0〜31**
- 野生・トレーナーのポケモンは生成時にランダム決定
- **本編中はプレイヤーに見せない。** エンドゲーム解放後に判定機能を開放する（§9）

## 4. 努力値（EV）

- 各ステータス **0〜252**、**合計上限 510**
- 4につきステータス1上昇（Lv100時）
- ポケモンを倒すと、その種族の「獲得努力値」が加算される
- **本編中は意識させない。** UIにも出さない

## 5. 性格（Nature）

- 25種。1つのステータスが ×1.1、別の1つが ×0.9。5種は無補正
- HP には影響しない
- **ミントで後から変更可能**（§9）

## 6. 特性（Ability）

- 種族ごとに通常特性1〜2種 + 隠れ特性1種
- 野生は通常特性からランダム。隠れ特性は特定の入手経路のみ
- **導入は v0.5**（[`battle-system.md`](battle-system.md) §12 で確定）。ただしバトルエンジンのフックは v0.1 で用意する
- **v0.5 実装済み。** カントー151種が使う48種を投入し、うち37種が戦闘中に働く。
  残り11種は天候・メロメロなど**機構がまだ無い**もので、`inert` として理由つきで持つ
  （[`battle-system.md`](battle-system.md) §12）。隠れ特性は v0.8 以降
- 極ティアのネームドは特性を選択して構築するため、**エンドゲームには必須**

## 7. 経験値とレベルアップ

### 経験値タイプ

種族ごとに6種類の成長曲線のいずれかを持つ。Lv100までの必要経験値が変わる。

| タイプ | Lv100 到達値 | 式（n = レベル） |
| --- | --- | --- |
| Erratic | 600,000 | 区分定義（レベル帯で式が変わる） |
| Fast | 800,000 | 4n³/5 |
| Medium Fast | 1,000,000 | n³ |
| Medium Slow | 1,059,860 | 6n³/5 − 15n² + 100n − 140 |
| Slow | 1,250,000 | 5n³/4 |
| Fluctuating | 1,640,000 | 区分定義（レベル帯で式が変わる） |

**計算せずテーブルとして `data/exp-tables.json` に持つ。** 100レベル × 6種類 = 600行にすぎず、
実行時に毎回計算する理由がない。

### 獲得経験値

第9世代準拠のレベル差スケーリング式を使う。倒した相手が自分より高レベルなら多く貰える。
これにより「レベルを上げすぎると効率が落ちる」自然な調整がかかる。

### 7.1 数値の出典（v0.9.5 で確定）

捕獲率・成長曲線・努力値配分・性別比・**与える経験値（`baseExp`）** は、
どれも原作の事実であって設計の余地がない。にもかかわらず v0.8 まで
**手入力（`baseExp` に至っては種族値合計からの推定）**だった。

| 出典 | 取れるもの | 使っている場所 |
| --- | --- | --- |
| `@pkmn/dex`（Pokémon Showdown） | 種族値・タイプ・特性・learnset・進化・性別比 | `tools/fetch-official.ts`（v0.8） |
| **veekun のデータセット**（`pokedex` パッケージ同梱・PokéAPI と同じ出典） | **捕獲率・成長曲線・努力値・`baseExp`・日本語名** | **`tools/fetch-numbers.ts`（v0.9.5）** |

対戦シミュレータのデータに捕獲率や `baseExp` が無いのは当然で、
**対戦の計算に使わないから**。用途が違うデータは出典も違う、というだけのことだった。

どちらも**生成時のみの devDependency**で、結果は TSV としてコミットする
（`source/species-numbers.tsv`）。ビルドを外部データに依存させない。

#### 突き合わせが手入力の誤りを3件見つけた

151種 × 5項目を照合したところ:

| 項目 | 結果 |
| --- | --- |
| 捕獲率・成長曲線・性別比 | **151件すべて一致** |
| 日本語名 | 2件（ニドラン♀♂ を「メス」「オス」と書いていた） |
| **努力値配分** | **3件が誤り** ―― パラセクト・ダグトリオ・ニョロボン |

**手入力は、量が少なくても必ず間違える。**
そこで `name` を突き合わせ専用の列として生成側に残し、
**species.tsv の表記が公式と違えば投入が止まる**ようにした。
種族値の BST チェックサム（v0.4）と同じ仕掛けを、名前にも掛けた形になる。

#### 出典の限界を記録する

veekun のデータは**第7世代（807種）まで**。第8・第9世代の種は載っていない。

そのため推定の道（種族値合計から `baseExp` を出す）は**消さずに残してある**。
公式値が無い種は推定で埋まり、**検証項目 #68 が「推定値である」と報告し続ける。**
`inert` な特性・未実装の技と同じ運用 ―― **入れていないことと入れ忘れを区別する。**

### 7.2 v0.12 で直した3つ（遊んで見つかったもの）

**1. 倒した相手のぶんは、勝っていなくても入る。**
UI 側が「勝ったときだけ」倒した相手を数えていた。
3体のうち2体を倒して負けると経験値が1も入らず、遊ぶ側からは
**「全員倒さないと経験値が入らない」**に見えていた。原作は倒れた瞬間に入る。

> なお**倒れた瞬間に入る**ところまでは、まだやっていない。
> レベルが上がったら戦闘中の実数値も変わらないと辻褄が合わず、
> それは live な `BattleState` を組み直す話になるため（v1.2 に送る）。

**2. 逃げただけでも1経験値が入っていた。**
山分けの下限（`Math.max(1, …)`）を、倒した相手が0体のときにも当てていた。
「けいけんちを もらった!」が毎回出るのはそのせい。
下限は**倒した相手が居るときだけ**当てる。

**3. 回復薬を使っても HPバーが動かなかった。**
`itemUsed` イベントが**文章しか運んでいなかった**。
表示層は `BattleState` を覗きにいかない造りなので、
イベントに乗っていない情報は存在しないのと同じになる。
使ったあとの HP・状態・対象を一緒に返すようにした。

> 「イベント列だけを見る」と決めた以上、**返し忘れは即バグになる。**
> 分担が正しいこととイベントが十分なことは別。

### 周回加速 ― 本作固有の仕組み

**殿堂入りした地方の数に応じて、経験値取得に倍率をかける。**

| 殿堂入り地方数 | 経験値倍率 |
| --- | --- |
| 0（1地方目） | ×1.0 |
| 1 | ×1.3 |
| 2 | ×1.6 |
| 3以上 | ×2.0（上限） |

倍率と上限は調整項目。**2周目以降の育成を短縮するのが目的**であり、
1周目の体験（原作のテンポ）は変えない。

## 8. 技の習得

| 経路 | 扱い |
| --- | --- |
| レベル技 | `Species.learnset` に定義。レベルアップ時に習得を提案 |
| わざマシン | 何度でも使える（第5世代以降準拠）。ショップ・BP交換で入手 |
| 教え技 | **BP交換に統合する**（§10） |
| タマゴ技 | **孵化システムを作らず、教え技に統合する**（§9） |

技は最大4つ。5つ目を覚えるときは入れ替えを選ばせる。

> **v0.8 の実装状況 ―【決定】公式データに差し替えた。**
> v0.4〜v0.7 の learnset は規則生成の暫定値だった。
> `@pkmn/dex` から第9世代（SV に居ない種は第8・第7世代）のレベル技表を取り込み、
> `packages/data/source/learnsets.tsv` としてコミットしている。
> 1種あたり平均10件。詳細は [`../game-plan.md`](../game-plan.md) §8.6。
>
> 技そのものは 105 → 247 件に増やした。原作で参照される技の68%を満たす。
> 残りは機構が未実装なので入れていない（`source/moves-todo.tsv` に理由つき）。

## 9. 個体調整 ― 孵化システムを作らない

**決定事項: 孵化・育て屋・遺伝システムは実装しない。**
代わりに、**アイテムによる直接編集**で個体値・性格・特性・タマゴ技を後から変更可能にする。

| 目的 | 手段 |
| --- | --- |
| 個体値を上げる | 「おうかん」系アイテムで指定ステータスを 31 にする |
| 性格を変える | 「ミント」で補正だけを変更する |
| 特性を変える | 「とくせいカプセル」「とくせいパッチ」（隠れ特性化） |
| 努力値を振る | 栄養ドリンク（直接加算）／努力値を下げる きのみ |
| タマゴ技を覚える | 「思い出し」＝ 教え技として BP で購入 |
| 個体値を確認する | ジャッジ機能（エンドゲーム解放後に開放） |

### なぜこうするか

1. **実装コストが1桁違う。** 孵化は 遺伝規則・預かりシステム・歩数カウント・性別・グループ判定 と、
   独立した機能が5つ必要になる。個人開発では割に合わない。
2. **第7世代以降の原作が実際にこの方向。** 不自然ではない。
3. **地方独立制と噛み合う。** 地方を9周する構造で、その上に孵化厳選まで乗せると総プレイ時間が破綻する。
4. **育成の深さは失われない。** エンドゲームで最適個体を作る体験は、
   孵化ではなくアイテム収集（＝ BP稼ぎ＝ 施設を遊ぶこと）に置き換わる。**エンドゲーム主軸の方針とも一致する。**

## 10. 育成アイテムの入手

| 段階 | 入手経路 |
| --- | --- |
| 本編中 | 基本的に入手できない（意識させない） |
| 殿堂入り後 | ジャッジ機能・栄養ドリンクを開放 |
| エンドゲーム | **BP交換が主経路**（おうかん・ミント・とくせいパッチ・わざマシン・教え技） |

これにより **「施設を遊ぶ → BPを稼ぐ → 個体を強化する → より上位の施設に挑む」** の
循環が成立する。エンドゲームが主軸である以上、育成資源の蛇口はそこに置く。

## 11. 進化

| 進化条件 | 扱い |
| --- | --- |
| レベル | そのまま |
| 道具使用 | そのまま |
| なつき度 | そのまま（なつき度は簡略実装。バトル参加・レベルアップで上昇） |
| 特定条件（時間・場所・持ち物・技） | そのまま |
| **通信交換** | **代替条件に置き換える（必須）** |

### 通信交換進化の代替

通信機能がないため、**そのままでは進化できない種が発生する**（ゴーリキー、ゴースト、ユンゲラー等）。
放置すると「全ポケモンが出る」が成立しない。

- **代替案A（採用）**: 専用アイテム「つながりのヒモ」使用で進化。第9世代に実際に存在するため自然
- 代替案B: 一定レベルで進化する（実装は最も簡単だが原作からの乖離が大きい）

「かわらずのいし」等の**交換時持ち物が必要な進化**（ストライク→ハッサム 等）は、
そのアイテムを持たせて「つながりのヒモ」を使う形に統合する。

### 実装（v1.1-b）

`UseEffect` に `evolveByItem` を1件足しただけで、19件の石と11件の交換が動いた。
**進化そのものはここでやらない** ―― 道具は「進化させたい」とだけ返し、
実際に種族を差し替えるのは既にある `evolve()`、演出と「やめる」は
既にある `offerEvolution()`（レベルアップの `canEvolve` と同じ道）。

```
{ kind: "evolveByItem", via: "item" }   … 進化の石（Evolution.item が自分と一致する枝）
{ kind: "evolveByItem", via: "trade" }  … つながりのヒモ（kind: "trade" の枝）
```

**`via: "trade"` は持ち物を見る。** 枝に `item` があるなら、その道具を
**持たせた状態**でだけ成立する ―― 上の統合をそのまま条件にしてある。
持たせ忘れを黙って通すと、「メタルコートを持たせる」という原作の手順が消える。

新しい `Condition` も、進化専用の分岐も作っていない。
**実測: カントー151種のうち入手できる種が 75 → 87 に増えた**（12種）。

## 12. レベル調整（施設）

エンドゲームの施設は Lv50 統一。ここで**双方向の調整**にする。

> **実レベルが50を超えていれば下げ、50未満であれば上げる。**

原作は「下げる」だけだが、上げる方向も許すことで
**エンドゲーム用に Lv50 まで育てる手間が消える。**
捕まえたばかりのポケモンをそのまま施設に持ち込める。

本作は9地方ぶんのポケモンを集める構造上、「集めた個体を使えるようにする」までの
摩擦を極力減らすべきなので、この方向を採る。実レベルとバトル用レベルは別概念として扱う。

### 技をどうするか ―「上げる」方向を許した結果の必然

原作の施設は**下げる**だけなので、技は常にそのまま使えた。
**上げる方向を許すと、この前提が崩れる。**

> Lv5 で捕まえた個体を Lv50 に引き上げても、覚えているのは Lv5 時点の技だけ。
> そのままでは戦えず、「持ち込める」という利点が意味を失う。

**決定: レベル同期で引き上げた個体は、同期後のレベルまでのレベル技を自動習得する。**

| 項目 | 扱い |
| --- | --- |
| 対象 | **引き上げたときのみ**。下げる場合は現在の技をそのまま使う |
| 習得内容 | `learnset` のうち同期後レベル以下の技から、**直近の4つ** |
| プレイヤーの上書き | 手動で技を選び直せる（編成画面で設定し、個体ごとに保存） |
| 実個体への影響 | **なし。** バトル用の一時的なものとして扱う |

手動で選び直せることが要点。自動習得はあくまで「そのまま持ち込んでも戦える」ための
既定値であり、育成した個体の技構成を勝手に書き換えるものではない。

**相棒のレベル同期**（[`regions.md`](regions.md) §6）にも同じ規則を適用する。
機構を共有しているので、規則も共有する。

## 13. 性別・色違い・ニックネーム

孵化システムを作らない（§9）判断の影響で、**設計から抜け落ちていた個体属性**。
いずれも `PokemonInstance` に必要。

### 性別 ―【決定】実装する（表示と技判定のみ）

孵化がないため、性別の役割は原作より小さい。それでも以下で必要になる。

- メロメロ・とっしん系など、**性別を参照する技・特性**
- 性別で姿が変わる種、性別で進化先が変わる種
- 種族ごとの性別比（`Species.genderRatio`。無性別・固定性別を含む）

遺伝に使わないため、**実装コストはごく小さい。** 落とす理由がない。

### 色違い ―【決定】実装する

**12文書のどこにも言及がなかったが、本作では落とせない。**

理由: 本作は「全ポケモンを集める」ことが3本の進行軸の1つ
（[`../game-plan.md`](../game-plan.md) §2）で、**収集がゲームの背骨になっている。**
色違いは収集の深さを一段増やすもので、コストに対して見返りが最も大きい要素の1つ。

| 項目 | 扱い |
| --- | --- |
| 判定 | 個体生成時に低確率で決定。以後不変 |
| 効果 | **見た目のみ。** 能力には一切影響しない |
| 図鑑 | 色違いを捕まえたかを別途記録する |
| 遭遇率の補正 | 「ひかるおまもり」相当を **BP交換に置く**（[`endgame.md`](endgame.md) §9） |

能力に影響させないのが要点。影響させると、対戦用の個体作りに
「色違い厳選」という別軸の作業が生まれ、**本章 §1 の「本編は育成を軽く」という方針と衝突する。**

### ニックネーム

捕獲時と、ボックスからいつでも変更できる。9地方を周回して集める構造では、
**個体への愛着を作る安価な手段**になる（相棒枠と同じ狙い）。

## 14. データ表現

```ts
type PokemonInstance = {
  uid: string;                 // 個体を一意に識別（共通ボックスで必要）
  species: SpeciesId;
  nickname?: string;           // 未設定なら種族名を表示
  level: number;
  exp: number;

  ivs: StatSpread;             // 0〜31
  evs: StatSpread;             // 0〜252, 合計510
  nature: NatureId;
  ability: AbilityId;
  gender: "male" | "female" | "genderless";
  shiny: boolean;              // 見た目のみ。能力に影響しない

  moves: { id: MoveId; pp: number; ppUps: number }[];
  item?: ItemId;

  currentHp: number;
  status?: StatusId;
  friendship: number;

  // ── 由来。共通ボックスが地方をまたぐため必須 ──
  meta: {
    caughtRegion: RegionId;
    caughtLevel: number;
    ball: ItemId;
    caughtAt: number;          // タイムスタンプ
  };
};

type StatSpread = { hp; atk; def; spa; spd; spe };
```

`meta.caughtRegion` は「どの地方で捕まえた個体か」の表示に使う。
9地方を周回する構造では、これが**プレイヤーの記録＝思い出**になる。図鑑表示にも使う。

## 15. 調整項目（実装後に決める）

- 周回加速の倍率と上限（×2.0 が妥当か、地方数の刻みは適切か）
- なつき度の上昇レート
- BP交換での育成アイテムの価格
- 本編中に努力値を完全に隠すか、殿堂入り前でも一部見せるか
- 「つながりのヒモ」の入手時期（早すぎると進化の達成感が薄れる）
- レベル調整の「上げる」方向が難易度を下げすぎないか
- 色違いの出現率と、「ひかるおまもり」相当のBP価格
- 性別比を種族ごとに原作準拠にするか、簡略化するか

## 14. v0.8 の実装状況

### 実個体（`PokemonInstance`）

v0.7 までの手持ちは `PartySpec`（設計図）で、バトルのたびに満タンで作り直されていた。
v0.8 でこれを実個体にした。**バトルの外に残るのは HP・PP・状態異常・経験値・なつき度だけ**で、
ランク補正や混乱は残さない ―― その場限りのものだから。

**レベルは持たない。** 累計経験値から導く。
2つ持つと必ずずれるので、正を1つに決める。

```
PokemonInstance ──instanceToSpec──> PartySpec ──toBattlePokemon──> BattlePokemon
                                       ↑                                │
                            出どころを1つに揃える場所            writeBack で書き戻す
```

出どころを union にせず、**設計図の側に「持ち込む値」（`uid` / `hpRatio` / `ppLeft`）を足した。**
「入口で1つの形に揃える」という `normalize.ts` の役目を、型の数でも守るため。
HP を割合で持つのは、施設のレベル同期で最大HPが変わっても
「半分減っている」という事実が保たれるようにするため。

### 戦闘後シーケンス

`battle-system.md` §10.5 の実行順どおり。**core は「何が起きたか」を返すだけ**で、
演出も、技を入れ替えるかどうかも、進化させるかどうかも UI が決める
（バトルが `BattleEvent[]` を返すのと同じ形）。

| 順 | 処理 | 実装の要点 |
| --- | --- | --- |
| 1 | 経験値 | 参加者で山分け。倒れた個体は貰わない |
| 2 | レベルアップ | 増えた最大HPぶんを今のHPにも足す（原作の挙動） |
| 3 | 技習得 | 枠が空いていれば自動。埋まっていれば**UI に聞く** |
| 4 | 努力値 | 合計510・各252で頭打ち |
| 5 | なつき度 | レベルが上がったターンは多めに |
| 6 | 進化 | **提案するだけ。** 実行は演出のあと。中断できる |
| 7 | 図鑑 | 対面で `seen`。`caught` を `seen` に戻さない |

### まだ暫定のもの

**与える経験値（`baseExp`）は種族値合計からの推定。**
原作の値（フシギダネ64・ピカチュウ112…）の正確なデータが手元に無い。
未進化の係数 0.20 は実測とよく合う（フシギダネ・キャタピー・コイキングは一致）が、
最終進化は ±15% ほどずれる。**効くのはレベルの上がる速さだけ**で、
バトルの正しさには影響しない。検証が毎回そう報告する。
