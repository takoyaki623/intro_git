# Pokémon Battle

ターン制のポケモン風バトルゲーム。交代・状態異常・能力変化・特性・持ち物ありの勝ち抜き式ローグライク。Vite + React + TypeScript。

もとは git の練習用リポジトリで、`first.txt` がその名残です。

## はじめかた

```bash
npm ci
npm run dev        # http://localhost:5173
```

**Node.js 22.22.2 以上**が要ります（`package.json` の `engines`）。
この数字は好みではなく、依存のうち一番厳しい `jsdom` から来ています——
`^22.22.2 || ^24.15.0 || >=26.0.0` で、**Node 20 は除外**されています
（`vite` と `oxlint` は 20.19 から動きますが、テストが動きません）。

満たない Node で `npm ci` すると npm が `EBADENGINE` を**警告として**出します。
止めたいなら `.npmrc` に `engine-strict=true` を書けばエラーになります。

必要なのは Node だけです。API キーも環境変数も外部サービスも要りません
（データは全部ローカル、`src/data/`）。

E2E だけブラウザ本体が別に要ります：

```bash
npx playwright install chromium
npm run e2e
```

## コマンド

| コマンド             | 内容                                 |
| -------------------- | ------------------------------------ |
| `npm run dev`        | 開発サーバ                           |
| `npm run build`      | 本番ビルド（型チェック込み）         |
| `npm run test`       | ユニットテスト（Vitest）             |
| `npm run test:watch` | テストを監視実行                     |
| `npm run coverage`   | カバレッジ                           |
| `npm run e2e`        | E2E テスト（Playwright、実ブラウザ） |
| `npm run typecheck`  | 型チェックのみ                       |
| `npm run lint`       | oxlint                               |
| `npm run format`     | Prettier で整形                      |
| `npm run check`      | typecheck + lint + test をまとめて   |

`npm run e2e` は Playwright が自前で用意したブラウザを使います。
サンドボックスや CI イメージなど、ブラウザが既にあってダウンロードが塞がれている環境では、
`PLAYWRIGHT_CHROMIUM_EXECUTABLE` にそのパスを渡すと既存のものを使います。

## 構成

```
src/
  domain/          ゲームのルール。UI に依存しない
    types.ts       18 タイプと相性表、相性計算
    entities.ts    Move / Species / BattlePokemon、レベル別ステータス
    damage.ts      ダメージ計算式（急所・タイプ一致・乱数）
    battle.ts      ターン処理、行動順、勝敗判定
    status.ts      状態異常 5 種のルール
    stages.ts      能力変化の段階と倍率
    abilities.ts   特性のルール
    items.ts       持ち物のルール
    run.ts         連戦の進行、難易度、戦闘間の回復
    rewards.ts     勝利報酬の抽選と適用
    ai.ts          相手の行動選択（技のスコアリングと交代判断）
    events.ts      バトル中に起きたことを表す構造化イベント
  data/            ポケモン 18 種と技 29 種のデータ
  ui/              日本語の文章、localStorage への保存と記録
  components/      表示だけを担当する React コンポーネント
e2e/               Playwright のシナリオ
```

`domain/` は React を一切参照していません。ルールだけを純粋な関数として置いてあるので、
UI を差し替えてもテストはそのまま通ります。

### ログについて

バトルのルールは文章ではなく `BattleEvent` を積み上げます。日本語の文言は
`src/ui/messages.ts` が組み立てます。分けてある理由は 2 つで、同じバトルを
別の言語で表示できること、そして UI が数値（ダメージ量など）を文章から
読み取らずに直接扱えることです。

### 乱数について

`calculateDamage` と `resolveTurn` は乱数生成器を引数で受け取ります
（省略時は `Math.random`）。テストでは決まった値を返す関数を渡すことで、
急所・命中・乱数幅を固定して結果を再現できます。
`src/test/rng.ts` にそのヘルパーがあります。

### 画面に出ている情報

カードにポケモンのタイプ、技ボタンに命中率（100% 未満のときだけ）と効果を出します。
相性そのものは表示しません。そこはプレイヤーが考える部分として残しています。

### 勝利報酬

勝つと 3 択が出て、1 つ選んでから次の相手に進みます。
効果は `src/domain/rewards.ts` の `REWARD_CONFIG` に集約してあります。
何もしない報酬は候補から外れるので、満タンなら回復は出ません。

### ランの終わり

**6 戦勝ち抜けばクリア**です。最後の 1 戦は**カイリューが 1 匹**で立ちはだかります
（ドラフトにも道中にも出ない、ボス専用の種族）。こちらは 3 匹なので、
数で押し切るのが勝ち筋です。

ドラゴン / ひこうは**こおりが 4 倍**なので、ドラフト画面の「こうげき ○○」を見て
氷の技を持つポケモンを取ってあるかどうかが、最後で効きます。

6 戦にした理由は測った結果です。8 戦だとボットで 5 ランに 1 ランしか
ボスまで届かず、ボスを見られないほうが問題でした。6 戦なら 3 ランに 1 回は
最後まで行き、5 ランに 1 回クリアできます。

### あそびかた

初回に自動で開き、以後はタイトル横のボタンからいつでも開けます。
書いてあるのは**画面から読み取れないことだけ**——ひんしがランの間もどらないこと、
「しゅぞくち」「こうげき ○○」が何か、交代が 1 ターン使うこと。

文言の数字は `RUN_CONFIG` などから読んでいます（`src/ui/guide.ts`）。
6 戦を 8 戦に変えたときに説明だけが嘘になるのを防ぐためで、テストで縛っています。

### おぼえられる わざ

技の入れ替えで提示されるのは、**その種族が覚えられる技だけ**です
（`src/domain/learnsets.ts`）。自分のタイプの技、汎用技（たいあたり・
どくどく など）、種族ごとの `learns` に挙げたマシン技の 3 つ。

遊んでもらって「絶対に覚えない技を覚えられるのが本家と違って違和感」という
指摘をもらって入れました。それまでは 49 技から無差別に引いていました。

### わかれ道

勝つたびに**次の相手を 2 択から選びます**。「ふつうの 3 びき」（短い戦いが 3 回、
ごほうび 1 つ）か、「つよいのが 1 ぴき」（Lv+10・HP 2.6 倍、ごほうび 2 つ）か。

**両方とも実際に組み立てて中身を見せます。**見えない分岐はコイン投げなので。

強敵は最初 Lv+3 で作りましたが、クリア率 40.6%（ふつう道 19.4%）で、
簡単なうえに報酬 2 つという壊れた選択でした。Lv+10 で 15.6%——
ごほうびをリスクで買う形になっています。

### だんかい（周回）

クリアすると**つぎのだんかい**が開きます。だんかいは 5 つあり、1 つ上がるごとに
相手の初期レベルが +1、そして**相手 1 匹が持ち物を持ちます**。
ルールは何も変わりません——同じ 6 戦を、強い相手で。

AI を賢くする案は測って捨てました。相手の賢さを 0.5 → 1.0 に振っても
プレイヤーのクリア率は 21.5% → 23.7% で誤差の範囲です。**相手は毎戦
入れ替わるので、相手のミスはその 1 戦で消えます。**難しくできるのは
こちらが持ち越す資源を削るものだけで、持ち物は戦闘を長引かせてそれをやります。

開いていないだんかいも鍵つきで見えています。進捗は `pokemon-battle:progress` に
ランとは別に保存され、一度開いたら下がりません。

### 交代ととんぼがえり

交代は 1 ターンを消費します。**とんぼがえり・ボルトチェンジ**は攻撃してから交代する
ので、その 1 ターン損がありません。押した時点で「あとに だすポケモン」を選びます。

交代なしのボットと交代ありのボットでクリア率が 14.6% → 20.1% になるので、
使う価値のある行動になっています（とんぼがえりを入れる前は 15.0% → 17.9% でした）。

### 反動技

すてみタックル・フレアドライブなどは与ダメージの一部が自分に返ります。
**ひんししたポケモンはランの間ずっと戻らない**ので、反動は二度と返ってこない
資源を払っていることになります。本家より重い判断です。

### わざを おぼえる

勝つと、報酬 3 択とは**別枠**で「この技を覚えますか？」が出ます。取っても
報酬は減りません。だれに覚えさせるか、どの技と入れ替えるかを選びます。

別枠にしたのは、3 択の 1 つにしたら罠になったからです。ランが終わるのは
「3 匹全員ひんし」のときだけなので、**体を増やさない報酬は構造的に負けます**。
技を取ると「そせい」を 1 回捨てることになり、実測でクリア率が
30.8% → 20.4% に落ちました。生き残りの選択とビルドの選択を別の層に分けています。

技は**ポケモンごと**に持ちます（`BattlePokemon.moves`）。種族から読んでいると、
入れ替えたときに同じ種族の相手の技まで書き換わってしまうためです。

### 種族と技

**31 種族・49 技**。18 匹だった頃は 11 のタイプに種族が 1 匹ずつしかおらず、
ドラフトの 6 匹にチャートのまるまる 1 列への答えが入らないことがありました。

種族値は本家のままです。弱い種族も入れてあります——6 匹の候補は、選ぶ価値の
ないものが混じっていて初めて選択になります。

増やしたら**腕前の差が 3.1 倍 → 6.6 倍**に広がりました。手持ちの技構成が
毎回変わるので、「とりあえず 1 番目を押す」が通用しなくなります。

### 難易度の調整

`src/domain/run.ts` の `RUN_CONFIG` に集約してあります。
相手のレベルの上がり方、戦闘間の回復量、手持ちの数がここだけで変わります。

ひんししたポケモンはランの間ずっと戻りません。これが勝ち抜きの緊張感を作っています。

相手の初期レベルはプレイヤーより低く設定してあります。同レベルから始めると
毎戦が五分勝負になり、期待連勝数が 1 になってしまうためです（実測）。
調整の根拠は [`docs/DESIGN.md`](docs/DESIGN.md) に数値で残してあります。

### ドラフト（手持ちを選ぶ）

ランの最初に **6 匹提示され、3 匹選びます**。カードには種族値合計・タイプ・
特性・攻撃できるタイプが出ます。選んだ順がそのまま手持ちの順で、1 番目が先発です。
もう一度押すと選択が戻ります。

固定の 3 匹だと毎回同じ入り口になってタイプ相性が解けた問題になり、
かといって完全に配るだけだと**引きがプレイヤーの判断より結果を左右していました**
（実測で 2 倍。[`docs/DESIGN.md`](docs/DESIGN.md) に数値）。選ばせることで、
1 勝もできないランが 20% から 9% に減りました。

候補の 6 匹は引いた瞬間に保存します。そうしないとリロードで引き直せてしまい、
気に入る 6 匹が出るまでリロードするのが最適手になるためです。

### 記録

最高連勝数とそのときのパーティは別枠で保存され、ラン終了画面と
連勝表示の横に出ます。0 連勝は記録しません。

### 進行の保存

`localStorage` に自動保存され、リロードしても続きから再開します。
保存するのは種族 ID・レベル・HP・状態異常・場に出ている位置・連勝数だけで、
種族や技のデータは読み込み時に `src/data` から復元します。
壊れた保存や古い形式は黙って捨てて、新しいランを始めます。
バトルログは保存しません（見終わった記録なので）。

### データを増やすには

`src/data/moves.ts` と `src/data/species.ts` に足すだけです。
`satisfies` を使っているので、型が合わなければコンパイルで止まります。

PokéAPI から取ってくることもできますが、ローカルに持つほうがテストが決定的になり、
オフラインでも動きます。

## 開発環境

このリポジトリには [SuperClaude Framework](https://github.com/SuperClaude-Org/SuperClaude_Framework) v4.3.0 を同梱しています。
clone してこのディレクトリで `claude` を起動すれば、**追加のインストール操作なしで**そのまま使えます。

内訳:

- **30 個のスラッシュコマンド** — `/sc:implement` `/sc:analyze` `/sc:brainstorm` `/sc:test` など
- **20 個の専門エージェント** — `@pm-agent` `@system-architect` `@security-engineer` など
- **6 個のスキル** — `confidence-check` `deep-research` `brainstorm` `troubleshoot` `pm` `token-efficiency`（会話内容に応じて自動起動）
- **3 個の hook** — セッション開始時の状況表示、終了前の未コミット確認、Write/Edit 後の自己検証
- **MCP サーバ 4 つ** — 下記参照

コマンド一覧は `/sc:help` で確認できます。

### MCP サーバについて

`.mcp.json` に 4 つ定義しています。いずれも API キー不要・無料です。

| サーバ              | できること                                                                                                               | 必要なもの                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------- |
| Context7            | ライブラリの公式ドキュメント参照                                                                                         | Node.js                                   |
| Sequential Thinking | 多段推論（`--think` 系フラグの土台）                                                                                     | Node.js                                   |
| Playwright          | 実ブラウザ操作。E2E テスト、スクリーンショット、フォーム入力、コンソールとネットワークの検査                             | Node.js + ブラウザ（初回に自動取得）      |
| Serena              | LSP による意味的なコード操作。シンボルのリネーム・参照検索・定義ジャンプ・診断、およびセッションをまたぐプロジェクト記憶 | [uv](https://docs.astral.sh/uv/)（`uvx`） |

Serena は PyPI の [`serena-agent`](https://pypi.org/project/serena-agent/)（本体は
[oraios/serena](https://github.com/oraios/serena)、MIT）を `uvx` 経由で起動します。
`uv` が入っていない場合は Serena だけ起動に失敗しますが、他の 3 つには影響しません。

初回起動時に Claude Code がこのプロジェクトの MCP サーバを信頼するか確認するので、承認してください。
使わない場合は `.mcp.json` を削除しても、コマンド・エージェント・スキルはそのまま動作します。

API キーが要る MCP サーバ（Magic、Morphllm、Tavily）は、`.mcp.json` が GitHub に
公開されるため意図的に入れていません。使う場合は `claude mcp add` で各自の環境に
入れるか、キーを `${VAR}` 形式で環境変数から読ませてください。

### 配置

```
.mcp.json                  MCP サーバ定義
.claude/
  settings.json            hook 定義
  commands/sc/             30 コマンド → /sc:*
  agents/                  20 エージェント
  skills/                  6 スキル
  superclaude/             参照ドキュメントと hook スクリプト
    VENDORED.md            同梱元・上流からの変更点
```

同梱の経緯と上流からの差分は [`.claude/superclaude/VENDORED.md`](.claude/superclaude/VENDORED.md) を参照してください。
