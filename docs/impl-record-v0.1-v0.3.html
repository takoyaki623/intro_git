02

バージョン別の実装

各版は前の版の上に積む。番号は実際の依存順序を表す。

v0.1

バトルの骨格

目的は機能の完成ではなく アーキテクチャの証明。設計が間違っていた場合に最小の傷で分かる形にする。データは5種・8技・攻撃技のみ。

実装

  • GameData interface による依存性注入 — core はデータを静的 import しない
  • toBattlePokemon — 3つの出どころ (実個体 / 設計図 / BattleSet) を入口で1つに正規化。levelOverride が後のレベル同期の入口
  • step(data, state, actions) — 「状態＋入力 → 新状態＋イベント列」の純関数。呼び出し元の state は不変
  • シード固定の疑似乱数 (xorshift32)。消費回数も状態に保持
  • ダメージ計算・18×18 タイプ相性・命中判定・急所・PP消費・優先度・素早さ順
  • Action 型は4種すべて定義し、move のみ実装

完了条件の達成

  • 達成 ランダムAI同士が1,000戦して例外なく決着 (無限ループ検出つき)
  • 達成 同一シードで2回流して結果が完全一致

実装して判明したこと

設計文書に「わるあがき」の記述が無かった。 PP が尽きると両者が行動不能になり、バトルが永久に終わらない。 完了条件が「1,000戦が例外なく決着する」なので、ここで必ず引っかかる。 文書レビューを5回やっても出てこなかった種類の穴で、実装したから見つかった。
v0.2

バトルの完成

骨格の上に、バトルとして成立するための要素を積む。データを20種41技へ拡張。

実装

  • 状態異常6種＋混乱 — タイプ無効・スリップダメージ・行動阻害・解除条件
  • 能力ランク補正 (−6〜+6) — 攻撃系と命中/回避で別の倍率表。急所は相手の防御上昇と自分の攻撃下降を無視
  • 交代 — 手持ちを配列化。ひんし後は pendingSwitch で交代を要求し、その間ターンを進めない
  • 変化技と効果レジストリの本格運用 — status / confuse / flinch / statChange / heal / multiHit を追加
  • 命中判定に命中/回避ランクを反映

完了条件の達成

  • 達成 全状態異常・全ランク補正・タイプ相性18×18 をテストで検証
  • 達成 1,000戦の完走テストを「手持ち2体・状態異常あり」に強化しても緑

設計原則の実証

41技すべてが JSON のデータだけで表現できた。 技を1件追加するのに書いたコードは 0行。 新規に書いたのは「効果の種類」6つぶんのハンドラだけ。 「コンテンツを1件足すコストをゼロに近づける」という設計方針の実測値になる。

設計文書の誤りを1件修正

  • もうどくは交代でカウンタが1に戻るだけで、通常のどくには戻らない。文書は「通常のどく扱いに戻る」としていたが原作の挙動と違っていた
v0.3

バトル画面

ブラウザで1戦を通しで遊べる状態にする。プレイヤー vs ランダムAI の 3対3。

実装

  • 技選択 (タイプ色・威力・PP)・交代・強制交代・HPバー・状態異常バッジ・能力ランク表示・手持ち残数・バトルログ
  • 高速モード3段階 (通常 / 高速 / ログのみ) — 周回に耐える操作の軽さ
  • seed 入力で同一バトルを再現 — 決定性が画面上の機能になる
  • アセット不在時のフォールバック (タイプ色の図形) — 通常動作の1つとして実装
  • ライト/ダーク両対応、520px 以下で1カラム

設計判断の変更

Phaser の導入を v0.7 (マップ探索) まで遅らせた。 v0.3 には絵が1枚も無く、設計上 Phaser が担当する「世界の描画」が存在しない。 「世界」が無い段階でゲームエンジンを入れる理由がないため、DOM だけで完結させた。

実機検証で見つけた不具合

  • 修正済 テーマが prefers-color-scheme だけで判定され、閲覧側の明示的なテーマ指定に追随しなかった
  • 修正済 スマホの長押し選択・ダブルタップ拡大が抑制されていなかった
  • 修正済 じこさいせいの PP が10 (第8世代の値)。第9世代では5

バトル仕様の詳細

ダメージ計算 (第9世代準拠)

基礎 = floor(floor(floor(2 × Lv / 5 + 2) × 威力 × A / D) / 50) + 2

補正の適用順:
  3. 急所 ×1.5      (相手の防御上昇と自分の攻撃下降を無視)
  4. 乱数 85〜100%   (16段階の整数から抽選)
  5. タイプ一致 ×1.5
  6. タイプ相性 ×0 / 0.25 / 0.5 / 1 / 2 / 4
  7. やけど ×0.5     (物理技のみ)
最低ダメージ 1 (相性0倍を除く)
手計算との一致を検証済み。 Lv50 ピカチュウ (とくこう70) の10まんボルト → ラプラス (とくぼう115・HP205) は 基礎26 → タイプ一致39 → 相性2倍 で 78。実装の出力と1の位まで一致する。 この値は reference-data.test.ts で固定してある。

5. ひんし判定   → 交代要求 または 決着

データの現状

検証済 正確なもの

種族値20種はすべて原作の値と一致。技41件の威力・命中・PP も原作どおり。ダメージ計算は手計算と完全一致。

概算 未確定のもの

learnset (何レベルで何を覚えるか) は概算。例: フシギダネのねむりごなを Lv9 としているが原作は Lv13。v0.4 で正式データに置き換える。

設計原則が実装にどう現れたか

設計上の主張実装での現れ方
コンテンツ追加のコストをゼロに近づける 41技のうち31件が効果つき。技追加で書いたコードは 0行
core はデータを持たない GameData interface。テストで2種2技だけを渡してもバトルが成立する
演出を飛ばしても結果が変わらない core は時間を持たず、UI は BattleEvent を消費するだけ。高速モードで実証
規律を人間の注意力に預けない タイプ相性の完全性・learnset の参照先・効果ハンドラの登録漏れをテストで検出
型を先に広げる Action を4種すべて定義。行動順処理が「道具・逃走・交代は技より先」の構造になっている
