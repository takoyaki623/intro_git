# 04. 捕獲・ボックス・図鑑

関連: [`progression.md`](progression.md) / [`regions.md`](regions.md) / [`../game-plan.md`](../game-plan.md)

---

## 1. 設計方針

本章は「**全てのポケモンが出る**」という最初の希望を、**実際に到達可能にする**ための章。

願望として書くだけでは達成できない。以下の3つを設計で担保する。

1. **収集の器**（共通ボックス）が地方をまたいで機能すること
2. **到達不能な種が1体も存在しない**こと（§7）
3. **9地方ぶん捕まえても作業にならない**こと

## 2. 捕獲判定

### 捕獲値の計算（第5世代以降準拠）

```
a = (3 × 最大HP − 2 × 現在HP) / (3 × 最大HP) × 種族の捕獲率 × ボール補正 × 状態異常補正
```

| 状態 | 補正 |
| --- | --- |
| ねむり・こおり | ×2.5 |
| まひ・どく・やけど | ×1.5 |
| なし | ×1.0 |

### 揺れ判定

```
b = 65536 / (255 / a)^0.1875
```

4回の判定を行い、全て成功で捕獲。`a ≥ 255` なら判定を飛ばして確定捕獲。
**揺れ回数はそのまま演出のイベント数になる**ので、`core` は「成功/失敗 + 揺れ回数」を返す。

## 3. ボール

ボールの補正は**条件付きの場合がある**（ネットボール = むし/みず に ×3.5 等）。
`if` の羅列にせず、[`battle-system.md`](battle-system.md) の技効果と同じく**データ駆動**にする。

```ts
type Ball = {
  id: ItemId;
  bonus:
    | { kind: "flat"; value: number }                              // ハイパーボール ×2
    | { kind: "guaranteed" }                                        // マスターボール
    | { kind: "conditional"; when: BallCondition; value: number; fallback: number };
};

type BallCondition =
  | { kind: "type"; types: Type[] }        // ネットボール
  | { kind: "turnCount"; op: "<=" | ">="; turns: number }  // クイック / タイマー
  | { kind: "alreadyCaught" }              // リピートボール
  | { kind: "levelBelow" }                 // ルアー等
  | ...;
```

ボールの追加 = JSONを1行。原作のボールを全種入れても実装は増えない。

## 4. 手持ちと地方ボックス

| 器 | 容量 | 有効範囲 |
| --- | --- | --- |
| 手持ち | 6 | 常時 |
| **地方ボックス** | 十分に大きい | **その地方のチャレンジ中のみ** |
| **共通ボックス** | 無制限 | **殿堂入り後・エンドゲーム** |

### 共通ボックスは地方チャレンジ中に開けない（重要）

**これがゲーム構造そのものを機械的に強制する仕組み。**

地方チャレンジ中に共通ボックスから引き出せてしまうと、
「各地方は現地のポケモンで攻略する」という設計が即座に崩壊する。
前の地方で育てたLv60を引っ張ってきて終わりになる。

```
地方チャレンジ中 ─── 使えるのは 手持ち + 地方ボックス のみ
        │
        │ 殿堂入り
        ▼
共通ボックスへ全個体を移送 ─── 以後エンドゲームで使用可能
```

- 殿堂入り時、その地方のボックスと手持ちの**全個体が共通ボックスへ移る**
- 殿堂入りメンバー6体は「殿堂記録」としても別途保存される（[`regions.md`](regions.md)）

### 4.1 送るのは一方通行で許す（v0.10 で決めた）

§4 の禁止は「開けない」と書いてあったが、**実装したら成立しなかった。**

殿堂入り（v1.0）まで共通ボックスは空のままなので、
**拠点のエンドゲームに持ち込める個体が1体も居ない**という状態になる。
エンドゲームが本作の重心である以上、これは受け入れられない。

> **決定: 共通ボックスへは、地方チャレンジ中でもいつでも送れる。**
> **引き出せるのは拠点だけ。**

§4 の意図は「**引き出せると本編の難易度が壊れる**」ことにあり、
送る方向はその意図を1つも侵さない。むしろ原作の「ボックスに預ける」に近くなる。

| 方向 | 地方チャレンジ中 | 拠点 |
| --- | --- | --- |
| 手持ち・地方ボックス → 共通ボックス | ⭕️ できる | ― |
| 共通ボックス → 手持ち | ❌ **できない**（設計の核心） | ⭕️ できる |

実装は `sendToCommonBox()`（`core/save/store.ts`）。
**地方の器から抜くのと共通ボックスに入れるのを1回の操作で行う** ――
別々にすると、片方だけ済んだ瞬間に個体が二重所属するか、どこにも属さなくなる。

### 個体の所属は常に1箇所（二重所属を禁止する）

1体の `PokemonInstance` が同時に複数の器に属することを禁じる。
所属は `RegionProgress.partyUids` / `RegionProgress.boxUids` / `global.boxUids` のいずれか**1つだけ**。

- **相棒**（[`regions.md`](regions.md) §6）は、地方チャレンジ開始時に
  `global.boxUids` から **`RegionProgress.partyUids` へ移す**。共通ボックスからは外れる
- その地方が終わる（殿堂入り／再挑戦でリセット）と `global.boxUids` に戻る
- `RegionProgress.partnerUid` は**所属ではなく目印**（レベル同期の対象を示すだけ）

二重所属を許すと「共通ボックスから逃がしたら地方の手持ちが消える」類の不整合が必ず出る。
検証項目に「全 uid がちょうど1つの器に属する」を入れる（[`data-schema.md`](data-schema.md) §6）。

### 殿堂入り後の地方に戻ったとき

殿堂入り後もその地方は歩ける（[`regions.md`](regions.md) §4）。このときの規則:

| 項目 | 扱い |
| --- | --- |
| 共通ボックス | **開ける。** チャレンジは終わっており、制限する理由がない |
| 手持ち | 共通ボックスから自由に編成できる |
| 相棒のレベル同期 | **解除**（クリア済みなので抑える必要がない） |

制限がかかるのは `state: "inProgress"` の間だけ、と定義する。
`state` を条件にすることで、判定が1箇所で済む。

## 5. 共通ボックス

9地方ぶん、1,025種を超える個体が集まる。**UI設計を誤ると使い物にならなくなる。**

必須の機能:

- **検索・フィルタ**: 種族 / タイプ / 捕獲地方 / レベル / 覚えている技 / 性格 / 特性 / お気に入り
- **ソート**: 図鑑番号 / 捕獲順 / レベル / 種族値合計
- **一括操作**: 移動・逃がす・お気に入り登録
- **チーム保存**: エンドゲーム用のパーティ編成を**名前付きで複数保存**できること

最後の1つは施設を周回する上で必須。毎回6体を選び直す構造だと、施設に挑む摩擦が大きすぎる。
（詳細は [`ui-flow.md`](ui-flow.md)）

## 6. 図鑑

### 状態

| 状態 | 条件 | 表示 |
| --- | --- | --- |
| 未発見 | — | シルエットも出さない |
| **見つけた** | 野生・トレーナー戦で対面した | 姿と名前のみ |
| **捕まえた** | 捕獲・進化・受け取り | 全情報（種族値・特性・技・出現場所） |

### 種類

- **全国図鑑**: 1,025種。進行軸の1つ（[`../game-plan.md`](../game-plan.md) §2）
- **地方図鑑**: 地方ごとの部分集合。地方チャレンジの達成度指標になる

地方図鑑の完成に報酬を置くことで、周回のたびに図鑑を埋める動機が生まれる。
全国図鑑は長期目標として据える。

## 7. 「全ポケモンが到達可能」の担保

**最初の希望が本当に成立するかは、ここで決まる。** 原作をそのまま移すと、必ず穴が空く。

### 原作由来の入手不能パターンと対処

| パターン | 対処 |
| --- | --- |
| **バージョン限定** | **撤廃する。** 1本のゲームなので分ける理由がない。出現率で差をつけるのは可 |
| **通信交換進化** | 「つながりのヒモ」で代替（[`progression.md`](progression.md) §11） |
| **通信交換限定の入手** | 撤廃。野生 or 報酬に置き換える |
| **幻のポケモン**（配布限定） | **エンドゲームの報酬に配置する。** ミュウ・セレビィ等 |
| **伝説のポケモン** | 各地方の固定シンボルとして配置 |
| **時間・季節依存の出現** | 実時間に依存させない。ゲーム内条件に置き換える |
| **特定バージョンのみのイベント** | 撤廃 |

**幻をエンドゲーム報酬に置く**のは、「全ポケモン収集」と「エンドゲームを遊ぶ動機」を
一本の線で繋げられるため。収集の最後のピースが施設の奥にある形になる。

### 到達可能性の自動検証（重要）

**入手経路をグラフとして辿り、到達不能な種を検出するスクリプトを `tools/` に置く。**

```
出発点: 野生出現テーブル / イベント配布 / 施設報酬 / 御三家
   │
   ├─ 進化（条件アイテムの入手可能性も辿る）
   ├─ 交換NPC
   └─ 報酬
   ▼
到達可能な種の集合 ← これが全1,025種と一致するかを検証
```

- CI で常時回す。**種やイベントを1件足すたびに全体の到達可能性が保証される**
- 到達不能な種を「未実装」と「設計ミス」に区別してレポートする
- 進化アイテムの入手経路まで辿るのが要点（アイテムが手に入らなければ進化先も入手不能）

願望をテストに変換する仕組み。これがないと、9地方を実装した後で
「この10種はどうやっても入手できない」が発覚する。

## 8. 捕獲を作業にしないための配慮

9地方ぶん捕まえるため、原作と同じ摩擦だと確実に破綻する。

- **一度捕獲した種はリピートボールの効果対象**になり、2周目以降の再捕獲が軽くなる
- **同種を何度も捕まえる必要はない。** 共通ボックスに残るため、収集目的の捕獲は原則1回で済む
  （地方チャレンジ中は共通ボックスを開けないので現地調達は発生するが、これは意図した設計）
- **図鑑登録済みの種は捕獲時の演出を短縮**できるようにする（スキップ設定）
- 手持ちが満杯のときは自動で地方ボックスへ送る（送り先の確認を挟まない）

## 9. データ表現

```ts
type EncounterTable = {
  id: EncounterTableId;        // v0.7 で location → id に変更（マップ側から参照する向きに揃えた）
  method: "grass" | "surf" | "fishing" | "cave" | "static" | "gift";
  entries: { species: SpeciesId; levelRange: [number, number]; rate: number }[];
};

type DexEntry = {
  species: SpeciesId;
  state: "unknown" | "seen" | "caught";
  shinyCaught: boolean;        // 色違いを捕まえたか（progression.md §13）
  firstCaughtAt?: number;
  caughtRegions: RegionId[];   // どの地方で捕まえたか
};

type BoxState = {
  scope: { kind: "region"; region: RegionId } | { kind: "global" };
  slots: PokemonInstance[];
  savedTeams: { name: string; memberUids: string[] }[];  // エンドゲーム用
};
```

`BoxState.scope` で地方ボックスと共通ボックスを同じ型で表現する。
別の型にすると移送処理が煩雑になる。

## 11. v0.8 の実装状況

### 捕獲

式は §2 のまま。**`core` が返すのは「捕まえたか」と「何回揺れたか」だけ。**
揺れる演出も、失敗したときの文言も UI が決める（バトルが `BattleEvent[]` を返すのと同じ形）。

**ボールを投げるのは1ターンを使う。** 削るか捕るかがそこで選択になる。
失敗したターンはこちらの技が出ず、相手だけが動く。

### ボールは9種、コードは1つ

`bonus` の種類だけがコードで、ボールそのものは `balls.tsv` の1行。

| ボール | 補正 |
| --- | --- |
| モンスター / スーパー / ハイパー | `flat` ×1 / ×1.5 / ×2 |
| マスター | `guaranteed` |
| ネット | `type` むし・みずに ×3.5 |
| クイック / タイマー | `turnAtMost` / `turnAtLeast` |
| ダーク | `terrain` 洞窟で ×3 |
| リピート | `alreadyCaught` 図鑑で捕獲済みなら ×3.5 |

原作のボールを全種入れても、増えるのは行だけ。

### 器 ―【最重要】1体はどこか1箇所にだけ属する

§4 の「二重所属を禁止する」を、**器を操作する関数を通してしか出し入れできない形**で実装した。
`addCaught` / `withdraw` / `deposit` / `release` / `reorder` はすべて最後に
`assertNoDuplicates` を通る。

- 手持ちは6匹。**あふれたらボックスへ**（どちらに入ったかを返し、UI の文言が変わる）
- **最後の1匹は預けられないし、逃がせない** ―― 手持ちが空だと野生戦が成立しない
- 手持ちがいっぱいのときの引き出しは、**入れ替える相手を指定させる**

### ボックスの画面は最小から

§5 は検索・フィルタ7種・ソート4種・チーム保存まで求めているが、
**それが要るのは数千個体になってから。** v0.8 では一覧・預ける・連れていく・逃がすだけ。

チーム保存の価値は「施設を何度も周回する」ようになって初めて出るもので、
それはセーブが本実装になってから（v0.9）。そのときまとめて足す。

### 捕まえた個体を施設に持ち込む（v0.8 の完了条件）

`Ruleset.teamSource: "own"` を解禁し、**バトルタワー・スーパー**をそれに切り替えた。
検証は v0.5〜v0.7 のあいだ `own` をエラーで弾いていた ―― 実個体が存在しなかったため。
機構が入ったので外した（`hallOfFame` は v1.0 なので弾いたまま）。

編成の画面は**候補の出どころが変わるだけ**で、選ぶ体験も検証（`validateTeam`）も同じものを使う。
実レベルが5でも50に同期されるので、**捕まえたばかりの個体をそのまま持ち込める**
（progression.md §12 の「双方向のレベル調整」がここで効く）。

### まだ無いもの

- **セーブ。** 捕まえてもリロードで消える（v0.9）
- **ショップ。** ボールはオーキドがくれる10個だけ（v0.9）
- **回復道具。** `Action.item` はボール専用で、きずぐすりは v0.9
