# 07. CPU AI 設計

関連: [`battle-system.md`](battle-system.md) / [`named-characters.md`](named-characters.md) / [`endgame.md`](endgame.md)

---

## 1. 設計方針

- `packages/core` に置く。バトルエンジンと同じく **純粋関数・シード固定乱数**で決定的に動く。
- **探索型ではなくヒューリスティック型**にする。
  ポケモンは情報不完全かつ分岐が大きく、ミニマックス探索はコストに見合わない。
  人間も「確定数」と「相性」で判断しているので、そこを模倣する方が体感の強さに直結する。
- 全レベルのAIが**同一のフレームワーク**（行動候補の列挙 → スコアリング → 選択）に載る。
  レベルの違いは**スコアリング関数だけ**。

```ts
function chooseAction(view: AiView, config: AiConfig, rng: Rng): Action;

type ScoredAction = {
  action: Action;
  score: number;
  reason: string;   // "相手を確1で倒せる" — デバッグ用。UIには出さない
};
```

`reason` を必ず持たせる。AIが不可解な行動をしたときに原因を追えないと、調整が不可能になる。

## 2. 情報の可視性（最重要の設計判断）

**AIに `BattleState` をそのまま渡さない。制限された `AiView` を渡す。**

そのまま渡すと、実装者が無意識に「相手の手持ち・技・持ち物を知っている」前提のコードを書いてしまう。
一度そうなると剥がせない。**型で強制的に縛る。**

```ts
type AiView = {
  own: { /* 自分の手持ち・技・持ち物・状態: 全て見える */ };
  foe: {
    active: { species; types; hpRatio; status; statStages; };  // hpRatio は割合のみ
    revealedMoves: MoveId[];      // 一度使われた技だけ
    revealedParty: SpeciesId[];   // 一度場に出た個体だけ
  };
  field: FieldState;
  turn: number;
};
```

### 全知AIは作らない

| 知識レベル | 内容 | 用途 |
| --- | --- | --- |
| `fair` | プレイヤーと同じ情報のみ。**既定値。** | ほぼ全ての場面 |
| `partial` | 相手の手持ちの**種族名だけ**が見える（技・持ち物は不明） | 施設の最高段位のみ |
| ~~`full`~~ | 全情報 | **採用しない** |

**強さは情報量ではなく思考の深さで作る。** これは「キャラらしさ優先」と同じ思想。
全知AIは理不尽で、プレイヤーが「読み」で勝つ余地を消してしまう。
極ティアのネームドも `fair` で戦い、それでも強い状態を目指す。

## 3. 難易度の2軸

難易度を「AIの種類」で刻むと3段階しか作れない。**2つの直交する軸**で連続的に調整する。

```ts
type AiConfig = {
  policy: "random" | "basic" | "smart";  // 思考の深さ
  mistakeRate: number;                    // 0.0〜1.0 一貫性
  knowledge: "fair" | "partial";
  tactic?: TacticId;                      // キャラの戦術（§5）
};
```

### 重要：最強を作ってから確率で劣化させる

弱いAIを強くしていくのではなく、**`smart` を完成させてから `mistakeRate` で弱くする。**
この向きの方が制御しやすく、難易度が予測可能になる。

`mistakeRate` = その確率で「最善手ではなく、スコア上位の中からランダムに選ぶ」。
完全なランダムに落とさないのがポイント。**明らかな悪手は打たないが、詰めが甘い**という
人間らしい弱さになる。

## 4. 各 policy の中身

### `random`（v0.1）

全ての合法手を等スコアで抽選。PP切れと交代不可だけ弾く。
v0.1 の完走テスト（1,000戦して例外なく決着する）用。

### `basic`

期待ダメージとタイプ相性だけを見る、1ターン先読みの貪欲法。

- 各技の期待ダメージを計算（乱数は期待値）
- **相手を倒せる技があれば最優先**
- タイプ相性が0倍の技は選ばない
- HPが一定割合を切ったら回復技・交代を候補に上げる
- 相手が無状態なら状態異常技を一定確率で
- 能力変化技は序盤（数ターン以内）のみ候補

確定数計算をしないため計算が軽い。一般トレーナーはこれで十分。

### `smart`

`basic` に以下を積む。ここが極ティアの中身。

| 思考 | 内容 |
| --- | --- |
| **確定数計算** | 自分が相手を倒すのに何発か / 相手が自分を倒すのに何発か。**乱数の下限・上限**の両方で計算し、「確定n発」と「乱数n発」を区別する |
| ↑の前提 | AIには相手の実数値が見えない（§2）。**種族値・推定レベル・`hpRatio` から推定して計算する。** 努力値は「役割から想定される標準的な配分」を仮定する |
| **先制判定** | 実効素早さを比較。まひ・こだわりスカーフ・優先度技を考慮 |
| **勝ち筋の確定** | 「先制できる + 確定1発」なら他を一切考えず攻撃する |
| **積みの価値評価** | 相手が自分を倒すのに3発以上かかるなら積む価値が高い。相手の状態異常も加味 |
| **交代の価値評価** | 交代を技と同じスコア軸に載せる。スコア = 交代先の対面有利度 − 交代中に受ける想定ダメージ |
| **タスキ・がんじょう考慮** | HP満タンの相手を確1で倒す計算をしたとき、割り引く |
| **状態異常の戦略的使用** | 積みアタッカーにまひ、物理アタッカーにやけど |
| **場作り** | ステルスロック等を序盤に高評価 |
| **戦術の遂行** | キャラの `tactic` に沿った行動を優先（§5） |

### 探索の深さ

**基本は1ターン先読み。** `smart` のみ、候補を上位3手に絞ってから2ターン目を評価する。
ブラウザで動かす以上、1ターンの思考時間に上限を設ける（調整項目）。

## 5. 戦術の遂行 ― AIで「キャラらしさ」を出す

[`named-characters.md`](named-characters.md) の `concept.tactic` を**AIが読んで遂行する。**

構築だけキャラらしくても、AIが普通に殴るだけなら「らしさ」は伝わらない。
**構築とAIの両方でキャラを表現する。**

| tactic | AIの挙動 |
| --- | --- |
| `sandstorm` | 砂が未展開なら始動を最優先。砂のスリップダメージ込みで確定数を計算。いわタイプの特防1.5倍を計算に含める |
| `trickroom` | トリル未展開かつ自分が低速なら最優先。残りターン数を数えて、切れる前に決めにいく |
| `rain` / `sun` | 天候始動 → 天候技の威力補正込みで確定数計算 |
| `setup` | 積みの価値評価の閾値を下げる（積極的に積む） |
| `stall` | 削り・回復・状態異常を高評価。攻撃技の優先度を下げる |
| `hyperOffense` | 交代の価値を下げ、常に最大打点を選ぶ |

`tactic` を持たないキャラは汎用スコアリングで動く。

## 6. 交代の扱い

交代判断を技選択と別ロジックにすると、必ず整合が取れなくなる。
**交代も同じスコア軸に載せる。**

```
交代スコア = 交代先の対面有利度
           − 交代ターンに受ける想定ダメージ
           − 現在のポケモンの積みランクの損失
           − 交代先が受ける追加ダメージ（ステルスロック等）
```

`basic` は「相性が悪い かつ HPが減っている」の単純条件のみ。
`smart` は上式で評価し、**不利対面でも押し切れるなら交代しない**判断ができる。

## 7. 用途別の設定

| 用途 | policy | mistakeRate | knowledge |
| --- | --- | --- | --- |
| v0.1 の完走テスト | `random` | — | fair |
| 序盤のザコトレーナー | `basic` | 0.5 | fair |
| 一般トレーナー | `basic` | 0.3 | fair |
| ジムリーダー（原作ティア） | `basic` | 0.15 | fair |
| 四天王・チャンピオン（原作ティア） | `smart` | 0.2 | fair |
| ネームド「本気」ティア | `smart` | 0.1 | fair |
| **ネームド「極」ティア** | `smart` | **0.0** | fair |
| 施設 低段位 | `basic` | 0.3 | fair |
| 施設 高段位 | `smart` | 0.0 | `partial` |

> この表は [`named-characters.md`](named-characters.md) §6 のAI欄を詳細化したもの。
> 数値はすべて調整項目で、1箇所の定数ファイルにまとめる。

## 8. テスト方針

AIは「バグっていても動いてしまう」ため、明示的に測る仕組みが要る。

- **相対勝率**: AI同士を1,000戦させ、`smart` が `basic` に対して有意に勝ち越すこと（目標70%以上）。
  **これが実装できているかの唯一の客観指標。**
- **`mistakeRate` の単調性**: 同一 policy で mistakeRate を上げると勝率が単調に下がること
- **決定性**: 同じシード・同じ盤面で必ず同じ行動を返すこと
- **悪手の回帰テスト**: 明らかな悪手を打たないことを個別に固定
  - 相性0倍の技を選ばない
  - PP切れの技を選ばない
  - 満タンの相手に回復技を撃たない
  - 確定1発で倒せて先制できるのに交代しない
- **思考時間**: 1ターンの思考が上限内に収まること

## 9. 調整項目（実装後に決める）

- 各スコアリングの重み係数（**全て1つの定数ファイルに集約する**）
- `mistakeRate` の各用途での具体値
- 積みの価値評価の閾値（「3発以上かかるなら積む」の3が妥当か）
- 1ターンの思考時間の上限
- `smart` の2ターン先読みが体感の強さに見合うか（見合わなければ1ターンに削る）
- 施設高段位の `partial` 知識が理不尽に感じられないか
