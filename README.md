# ポケットモンスター ― ドットのぼうけん

ブラウザで動く、ポケモン風のドット絵RPG。
**ビルド不要・npm依存ゼロ・外部アセットゼロ**。HTML と CSS と素の JavaScript だけでできています。

マップ探索 → 草むらでエンカウント → ターン制バトル → 捕獲 → レベルアップ → 進化 → セーブ
という一連の流れがひととおり遊べます。
ショップでの売り買い、落ちているどうぐ拾い、トレーナー戦（視線に入ると声をかけられます）、
ジムとバッジ、段差の飛び降り、なみのり、つり にも対応しています。

---

## 遊びかた

ES modules を使っているので `file://` での直接オープンはできません（ブラウザの CORS 制限）。
同梱の `serve.py` で配信してください。

```bash
python3 serve.py
```

PC で遊ぶ URL と、**同じ Wi-Fi のスマホで遊ぶ URL** が表示されます。
インターネットには公開されず、自宅のネットワークの中だけで完結します。

```
  このPCで遊ぶ:
      http://localhost:8000

  同じ Wi-Fi のスマホで遊ぶ（この URL を入力）:
      http://192.168.1.23:8000
```

`python3 -m http.server 8000` や `npx serve .` でも動きますが、
その場合スマホ用の URL は自分で調べる必要があります。

### そうさ

| | キーボード | スマホ |
|---|---|---|
| いどう | ← ↑ → ↓ / WASD | 十字キー（指を滑らせて方向を変えられます） |
| けってい (A) | Z / Enter / Space | A ボタン |
| キャンセル (B) | X / Esc / Backspace | B ボタン |
| メニュー | C | ☰ ボタン |
| ダッシュ | Shift + いどう | ― |

操作パッドは**直前に何で操作したか**で出入りします。画面を指で触れば出てきて、
キーを叩けば引っ込みます。タッチ対応のノートPCでも、スマホに外付けキーボードを
繋いだ場合でも、そのとき使っているほうで遊べます。

## スマホで遊ぶ

縦持ち・横持ちのどちらでも遊べます。縦持ちだと画面幅いっぱいにゲームが広がり、
下半分が操作パッドになります。横持ちなら左右の余白にパッドが出ます。

1. PC で `python3 serve.py` を実行する
2. 表示された `http://192.168.x.x:8000` をスマホのブラウザに入力する

インターネットには出ません。**PCとスマホが同じ Wi-Fi につながっている必要があります。**

**ホーム画面に追加**すると、アドレスバーの無い全画面で起動します
（iOS: 共有 → ホーム画面に追加 ／ Android: メニュー → ホーム画面に追加）。
セーブはブラウザの localStorage に入るので、同じ端末の同じブラウザなら残ります。
PC とスマホでセーブは共有されません（それぞれ別々に進みます）。

### PC が使えないとき ― 1枚のHTMLに畳む

サーバーを立てられない場面のために、全部を1ファイルにまとめられます。

```bash
node tools/bundle.mjs
# → dist/pokemon-dot-adventure.html
```

このファイルは**単体で完結**していて、外部への通信が一切ありません。
スマホに保存してブラウザで開けばそのまま遊べます（`file://` でも動きます）。
オフラインでも動き、セーブも効きます。

ふだんの `src/` は `<script type="module">` で読み込んでいるため相対パスの取得
＝HTTP配信が前提ですが、バンドル版は各モジュールを関数に包んで小さなレジストリに
登録し、import をその呼び出しに書き換えているので、その前提が要りません。

### つながらないとき

- **PCのファイアウォール** … 初回は Python の通信許可を聞かれます。許可してください
- **ゲスト用 Wi-Fi** … 端末同士の通信を遮断している設定（AP アイソレーション）が多いので、通常の Wi-Fi につなぎ直してください
- **IP が複数表示される** … 有線と無線の両方につながっている場合です。上から順に試してください
- **`serve.py` を止めるとつながらなくなります** … 遊んでいる間は PC で起動したままにしてください

### さいしょの ながれ

1. タイトルで **はじめから** を選ぶ
2. むらの まんなかに いる **はかせ** に はなしかけて、御三家（フシギダネ / ヒトカゲ / ゼニガメ）から1匹もらう
3. むらの **きた** へ ぬけて **１ばんどうろ** へ
4. こい みどりの **くさむら** を あるくと やせいの ポケモンが とびだす
5. HPを けずってから **バッグ → モンスターボール** で つかまえる
6. よわったら **ポケモンセンター**（むらの まんなかの あかい やね）か **じぶんのいえ の ベッド** で かいふく
7. メニューの **レポート** でセーブ

## 中身

| ファイル | 役割 |
|---|---|
| `index.html` | canvas と `<script type="module">` だけ。ここが唯一のエントリ |
| `tests.html` | 依存ゼロのブラウザ内アサーション（計算式とデータ整合性 1000件超） |
| `src/core/` | 描画スケール・ゲームループ・入力・シーンスタック・乱数・セーブ・音 |
| `src/engine/` | ピクセル文字列→canvas のベイク、日本語ビットマップ字形、テキスト枠、メニュー、UI部品 |
| `src/data/` | タイプ相性・技・種族・どうぐ・タイル・マップ・ドット絵 |
| `src/game/` | 計算式・個体・バトル進行・エンカウント・ワールド・ゲーム状態 |
| `src/scenes/` | 各画面 |

### 設計で決めていること

- **PC は 256×192 を整数倍だけで拡大する。** PC は等倍が 1 デバイスピクセルなので、半端な倍率にすると 1ドットの幅が場所によって変わり、ドット絵が濁る。ただしスマホは別扱い ―― 256 の整数倍は 256/512 しかなく、幅 390px の端末では 1倍（画面の 66%）に落ちてまるで遊べない。スマホは `devicePixelRatio` が 2〜3 あって 1ドットあたりの誤差がデバイスピクセル 0.5 未満に収まるので、こちらは箱いっぱいまで引き伸ばしている。
- **バトル進行はジェネレータで書く。** 「メッセージ→A待ち→アニメ→HPバー→レベルアップ→技忘れ確認→進化」という深い入れ子を、手書きの状態機械でやると継続を自前のスタックで持つ羽目になる。
- **導出できる値はセーブに入れない。** ステータスはロード時に種族値と個体値から計算し直すので、計算式のバグを直すと既存のセーブにも自動で反映される。
- **日本語は実行時に字形を焼く。** 日本語Webフォントの同梱は数MBになり「外部アセットなし」に反する。かといって拡大 canvas への `fillText` は滲む。必要な文字だけ 12px で焼いてアルファを2値化し、等倍で貼る。
- **ドット絵は文字列で書く。** `'....oooo....'` のような1文字=1ピクセルの配列。差分が読めて、どのエディタでも手で直せる。

### テスト

```bash
python3 serve.py
# → http://localhost:8000/tests.html
```

`ALL PASS` と出れば全部通っています。中身は計算式（ステータス・ダメージの乱数幅・捕獲率・成長曲線）と、
データ整合性（習得技が実在するか、進化先が実在するか、マップの行幅が揃っているか、ワープの着地が通行可能か…）。
このプロジェクトのバグはほとんどがデータの打ち間違いなので、後者がよく効きます。

## つくりかたのメモ

### いま入っているデータを一覧する

```bash
node tools/datasheet.mjs
# → dist/datasheet.html
```

ポケモン・わざ・どうぐ・マップ・タイプ相性を1枚にまとめた資料ページを
`src/data/` から生成します。手で書き写さないので値がズレません。
「誰も覚えないわざ」「入手経路のないどうぐ」といった穴も自動で洗い出します。

### あたらしい ポケモンを ふやす

1. `src/data/sprites/monsters.js` に 24×24 のドット絵を足す（行の長さは必ず24）
2. `src/data/species.js` に種族データを足す
3. `tests.html` を開いて `ALL PASS` を確認
4. `node tools/datasheet.mjs` で資料を作り直す

### あたらしい マップを ふやす

1. `src/data/maps/` に1ファイル作る（文字列グリッド＋`legend`）
2. `src/data/maps/index.js` に登録する
3. どこかのマップの `warps` から行き先として指すのを忘れずに

### どうぐを 置く・売る

マップに落とすには `items` に1行足します。`flag` は拾ったかどうかの記録で、
**マップをまたいで一意**にしてください（被ると片方を拾ったとき両方消えます）。

```js
items: [
  { x: 17, y: 2, item: 'かみなりのいし', n: 1, flag: 'item_forest_stone' },
],
```

店を出すには NPC のセリフに `shop` を混ぜます。売値は買値の半分（切り捨て）です。

```js
lines: ['いらっしゃいませ！', { shop: ['モンスターボール', 'きずぐすり'] }],
```

どちらも `tests.html` が実在チェックと `flag` の重複チェックをします。

### トレーナーを ふやす

1. `src/data/trainers.js` に1件足す（肩書き・名前・手持ち・しょうきん・セリフ）
2. マップの `npcs` に `trainer: 'そのキー'` と `dir` / `sight` を書いて置く
3. `tests.html` が「視線が0マスになっていないか」「同じ人を二度置いていないか」を見ます

倒したかどうかは `trainer_<キー>` というフラグで覚えるので、セーブ形式は増えません。
ジムリーダーには `badge` を書くと、勝ったときに `badge_<id>` が立ちます。

### 地形の ギミック

| | 書きかた |
|---|---|
| 段差 | `legend` に `'L': 'ledge'` を足してタイルを置く。北からだけ飛び降りられます |
| 水 | `'~': 'water'`。マップに `water: { surf, fish }` を足すと、なみのり／つりの相手が決まります |

なみのりは、手持ちの誰かが `field: 'surf'` の技（＝なみのり）を覚えていれば使えます。
つりは `use.kind === 'rod'` のどうぐを持っていれば使えます。どちらも
**水辺を向いて A** で始まります（バッグからではありません）。

`tests.html` が「段差の着地点が歩けるか」「水があるのに遭遇テーブルが無いマップ」を見ます。

## 公開する場合（いまは公開していません）

このゲームはローカル配信だけで遊ぶ前提にしてあります。インターネットには出していません。

もし公開したくなったら、GitHub Pages なら Settings → Pages → Deploy from a branch →
`/ (root)` でそのまま動きます（`index.html` がリポジトリ直下にあり、import はすべて
相対パス＋`.js` 拡張子つきなので）。

ただし GitHub Pages に無料プランでのアクセス制限はなく、**URL を知っている人は誰でも
開ける状態**になります。検索エンジンにも拾われ得ます。公開する前に、下の「ことわり」を
もう一度お読みください。
