# 05. 地方チャレンジ

関連: [`capture.md`](capture.md) / [`progression.md`](progression.md) / [`endgame.md`](endgame.md) / [`../game-plan.md`](../game-plan.md) 4章

## 1. 設計方針

地方チャレンジは本作の「本編」だが、**ゲームの重心はエンドゲームにある**。
地方は「ポケモンを集め、愛着を作る層」であり、そこで完結させる必要はない。

各地方が満たすべき条件は3つ。

1. **完全に独立していること。** 他の地方の進行状況に依存しない
2. **単体で完結していること。** 1地方だけ遊んで終わっても満足できる
3. **追加が既存に影響しないこと。** 新地方の追加でカントーの調整をやり直さない

## 3. 解放条件 ―【決定】ロックしない

**決定事項: 全ての地方を最初から選択可能にする。段階解放はしない。**

代わりに、各地方に**難易度の目安を表示**し、初回は カントー を推奨表示する。

### 理由

- **バランス上ロックする理由がない。** 各地方は Lv5 から始まる独立した1本なので、
  どこから始めても成立する。ロックは地方独立制の最大の利点（順不同）を殺すだけになる。
- **開発上の利点が大きい。** 新地方を追加したら**その瞬間に誰でも遊べる**。
  段階解放だと「新地方を遊ぶには前の地方をクリアする必要がある」となり、
  追加した内容が既存プレイヤーにすぐ届かない。
- **好きな地方から始められる**のは、原作ファンにとって素直に嬉しい。

進行に対する報酬は、ロック解除ではなく**経験値の周回加速**
（[`progression.md`](progression.md) §7）と**エンドゲームのカップ解放**が担う。

## 4. チャレンジの構造

```
地方を選択
   │
   ├─ 御三家を選ぶ
   ├─ 相棒を1体連れて行く（2地方目以降・任意）§6
   │
   ▼
8バッジを集める ─── 順序は原作準拠
   │
   ▼
四天王 → チャンピオン
   │
   ▼
殿堂入り
   │
   ├─ 手持ち・地方ボックスの全個体が共通ボックスへ移送
   ├─ 殿堂記録を保存 §7
   └─ 経験値の周回加速が1段階上がる
```

- レベル帯は原作準拠（開始 Lv5 前後 → チャンピオン Lv55〜60 前後）
- **殿堂入り後もその地方を歩ける**（未捕獲の種を集めるため）。図鑑の完成には必要
- 同じ地方を再挑戦（リセットして最初から）できるようにする。ただし共通ボックスの中身は消えない

## 5. 地方をまたぐもの・またがないもの

**この表が地方独立制の定義そのもの。** 曖昧にすると必ず破綻する。

| 要素 | 持ち越し | 理由 |
| --- | --- | --- |
| 手持ちポケモン | ❌ | 構造の根幹（相棒1体のみ例外） |
| **捕まえたポケモン** | ✅ | 共通ボックスへ蓄積。収集の軸 |
| **図鑑** | ✅ | 全国図鑑は進行軸の1つ |
| **BP** | ✅ | エンドゲーム共通通貨 |
| **経験値の周回加速** | ✅ | 殿堂入り数に応じた恒久ボーナス |
| **殿堂記録** | ✅ | 恒久保存 |
| お金 | ❌ | 序盤バランスが壊れる |
| 道具・わざマシン | ❌ | 同上 |
| 育成アイテム | ❌ | 本編中は使わせない（[`progression.md`](progression.md) §10） |
| バッジ | ❌ | 地方ごとに独立 |

原則: **収集・記録は持ち越す。戦力・資源は持ち越さない。**

## 6. 相棒枠 ―【決定】採用する

**決定事項: 2地方目以降、前の地方から1体だけ連れて行ける。バトルにも参加できる。**

### レベル同期で解決する

素直に連れて行くと Lv60 が序盤を蹂躙して構造が壊れる。そこで、

> **相棒のレベルを、その地方の進行度（バッジ数）に同期させる。**

[`progression.md`](progression.md) §12 で定義した**施設のレベル調整機構をそのまま流用する**ため、
実装コストはほぼゼロ。実レベルは保持したまま、バトル時のみ同期後の値を使う。

| バッジ数 | 相棒のバトル時レベル |
| --- | --- |
| 0 | 該当地方の序盤帯 |
| 4 | 中盤帯 |
| 8 | 終盤帯 |
| 四天王戦 | 四天王帯 |

これにより相棒は**常に主力として使えるが、決して壊れない**。

### 規則

- 連れて行けるのは**1体のみ**。地方開始時に選び、その地方の間は変更できない
- 相棒は共通ボックスから選ぶ（＝殿堂入り済みの個体から選べる）
- 相棒も地方のボックスに預けられるが、他の地方の個体と入れ替えることはできない

### なぜ入れるか

地方独立制の唯一の弱点は「育てた手持ちを毎回失う」喪失感。
1体だけ連れて行けることで、**プレイヤーの「相棒」という物語が9地方を貫通する。**
戦力バランスを壊さずにこれを実現できるなら、入れる価値が十分にある。

## 7. 殿堂記録

殿堂入り時に、**そのときの手持ち6体をスナップショットとして永久保存する。**

```ts
type HallOfFameEntry = {
  region: RegionId;
  clearedAt: number;
  attempt: number;                    // 同じ地方の何周目か
  members: PokemonSnapshot[];         // 6体。個体値・技・レベルまで丸ごと
  playTime: number;
  badgeOrder: GymId[];
};
```

- 個体そのものは共通ボックスに移るが、**殿堂記録は「そのときの姿」を凍結**して残す
  （後で技構成を変えても、殿堂入り時の姿が残る）
- **エンドゲームで「殿堂チーム」としてワンタッチ編成できる**ようにする。
  施設に挑むときの編成の手間が減り、殿堂記録が実用的な意味を持つ

## 8. 地方の追加手順（1地方 = 1リリース）

新地方を1つ追加するのに必要な作業。**コード変更が発生しないことが目標。**

1. マップデータ（町・ルート・ダンジョン）
2. 野生出現テーブル（[`capture.md`](capture.md) §9）
3. 地方図鑑の定義
4. 一般トレーナーの配置とパーティ
5. ネームド（ジムリーダー8・四天王4・チャンピオン・ライバル・組織ボス）の3ティア
   （[`named-characters.md`](named-characters.md) §8 の手順に従う）
6. イベント・NPC会話
7. 到達可能性の検証スクリプトを回す（[`capture.md`](capture.md) §7）

**7番が完了条件。** これを通らない限り地方をリリースしない。

### 構造が特殊な地方

アローラ（島巡り）・パルデア（オープンワールド）は「8ジム→四天王」に当てはまらない。
`RegionDefinition` に**チャレンジ構造をデータとして持たせ**、
ジム制以外を表現できるようにしておく。後から特例コードを足す形にしない。

```ts
type RegionDefinition = {
  id: RegionId;
  name: string;
  difficulty: 1 | 2 | 3;              // 選択画面に出す目安
  challenge:
    | { kind: "gyms"; gyms: GymId[]; elite4: NamedId[]; champion: NamedId }
    | { kind: "trials"; trials: TrialId[]; kahunas: NamedId[]; champion: NamedId }
    | { kind: "open"; routes: RouteId[][]; champion: NamedId };
  levelBands: { badges: number; min: number; max: number }[];  // 相棒の同期にも使う
  starters: [SpeciesId, SpeciesId, SpeciesId];
  dex: SpeciesId[];
};
```

`levelBands` は**相棒のレベル同期（§6）と、そのままレベルデザインの定義を兼ねる。**
1箇所に持つことで、両者がずれることがなくなる。

## 9. 調整項目（実装後に決める）

- 相棒のレベル同期が「強すぎ／弱すぎ」にならないか（個体値・努力値は同期しないため、
  最適化個体の相棒は多少強い。これを許容するか）
- 難易度表示（★）の基準
- 同じ地方の再挑戦を何周まで記録するか
- 殿堂入り後のマップ開放範囲
- 各地方のレベル帯を原作からどれだけ調整するか
