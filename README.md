# ポケットモンスター ― ドットのぼうけん

ブラウザで動く、ポケモン風のドット絵RPG。
**ビルド不要・npm依存ゼロ・外部アセットゼロ**。HTML と CSS と素の JavaScript だけでできています。

マップ探索 → 草むらでエンカウント → ターン制バトル → 捕獲 → レベルアップ → 進化 → セーブ
という一連の流れがひととおり遊べます。

---

## 遊びかた

ES modules を使っているので `file://` での直接オープンはできません（ブラウザの CORS 制限）。
ローカルで配信してから開いてください。

```bash
python3 -m http.server 8000
# → ブラウザで http://localhost:8000 を開く
```

`npx serve .` や `npx http-server -p 8000` でも同じです。

## スマホで遊ぶ

縦持ち・横持ちのどちらでも遊べます。縦持ちだと画面幅いっぱいにゲームが広がり、
下半分が操作パッドになります。横持ちなら左右の余白にパッドが出ます。

### GitHub Pages で公開して、スマホから開く

`.github/workflows/pages.yml` が入っているので、push すると自動で公開されます
（Pages 自体もこのワークフローが有効化するため、Settings を手で触る必要はありません）。

1. GitHub のリポジトリ → **Actions** タブで `Deploy to GitHub Pages` の完了を待つ（1〜2分）
2. `https://takoyaki623.github.io/intro_git/` が開けるようになります
3. スマホでもPCでも、同じ URL をブラウザで開くだけ

うまく動かない場合は **Settings → Actions → General** で
`Workflow permissions` が `Read and write permissions` になっているか確認してください。

**ホーム画面に追加**すると、アドレスバーの無い全画面で起動します
（iOS: 共有 → ホーム画面に追加 ／ Android: メニュー → ホーム画面に追加）。
セーブはブラウザの localStorage に入るので、同じ端末の同じブラウザなら残ります。

> 公開すると誰でもアクセスできる状態になります。実在のポケモン名を使っている点は
> 「ことわり」の項もあわせてご確認ください。

### 公開せずに、同じ Wi-Fi のスマホから開く

PC でサーバーを立て、`--bind` を外して LAN に開放します。

```bash
python3 -m http.server 8000            # PC の IP を調べる: ipconfig / ifconfig
# スマホのブラウザで http://<PCのIPアドレス>:8000 を開く
```

## 中身

| ファイル | 役割 |
|---|---|
| `index.html` | canvas と `<script type="module">` だけ。ここが唯一のエントリ |
| `tests.html` | 依存ゼロのブラウザ内アサーション（計算式とデータ整合性 1000件超） |
| `src/core/` | 描画スケール・ゲームループ・入力・シーンスタック・乱数・セーブ・音 |
| `src/engine/` | ピクセル文字列→canvas のベイク、日本語ビットマップ字形、テキスト枠、メニュー、UI部品 |
| `src/data/` | タイプ相性・技・種族・どうぐ・タイル・マップ・ドット絵 |
| `src/game/` | 計算式・個体・バトル進行・エンカウント・ワールド・ゲーム状態 |
| `src/scenes/` | 各画面 |

### 設計で決めていること

- **PC は 256×192 を整数倍だけで拡大する。** PC は等倍が 1 デバイスピクセルなので、半端な倍率にすると 1ドットの幅が場所によって変わり、ドット絵が濁る。ただしスマホは別扱い ―― 256 の整数倍は 256/512 しかなく、幅 390px の端末では 1倍（画面の 66%）に落ちてまるで遊べない。スマホは `devicePixelRatio` が 2〜3 あって 1ドットあたりの誤差がデバイスピクセル 0.5 未満に収まるので、こちらは箱いっぱいまで引き伸ばしている。
- **バトル進行はジェネレータで書く。** 「メッセージ→A待ち→アニメ→HPバー→レベルアップ→技忘れ確認→進化」という深い入れ子を、手書きの状態機械でやると継続を自前のスタックで持つ羽目になる。
- **導出できる値はセーブに入れない。** ステータスはロード時に種族値と個体値から計算し直すので、計算式のバグを直すと既存のセーブにも自動で反映される。
- **日本語は実行時に字形を焼く。** 日本語Webフォントの同梱は数MBになり「外部アセットなし」に反する。かといって拡大 canvas への `fillText` は滲む。必要な文字だけ 12px で焼いてアルファを2値化し、等倍で貼る。
- **ドット絵は文字列で書く。** `'....oooo....'` のような1文字=1ピクセルの配列。差分が読めて、どのエディタでも手で直せる。

### テスト

```bash
python3 -m http.server 8000
# → http://localhost:8000/tests.html
```

`ALL PASS` と出れば全部通っています。中身は計算式（ステータス・ダメージの乱数幅・捕獲率・成長曲線）と、
データ整合性（習得技が実在するか、進化先が実在するか、マップの行幅が揃っているか、ワープの着地が通行可能か…）。
このプロジェクトのバグはほとんどがデータの打ち間違いなので、後者がよく効きます。

## つくりかたのメモ

### あたらしい ポケモンを ふやす

1. `src/data/sprites/monsters.js` に 24×24 のドット絵を足す（行の長さは必ず24）
2. `src/data/species.js` に種族データを足す
3. `tests.html` を開いて `ALL PASS` を確認

### あたらしい マップを ふやす

1. `src/data/maps/` に1ファイル作る（文字列グリッド＋`legend`）
2. `src/data/maps/index.js` に登録する
3. どこかのマップの `warps` から行き先として指すのを忘れずに
